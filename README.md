## Purpose
This artifact contains the This artifact contains the related documentation for the issue characterization process and the NeuroAccess pipeline for the paper ***"NeuroAccess: Agentic Persona-Aware Detection of Neurodivergent Accessibility Issues in Mobile Apps"***

The 'Issue-Characterization' directory contains the 44 identified Success Criteria (SCs) that explicitly mention benefits for neurodivergent users, the mapping of 28 of these SCs to the Design Patterns (DP) define in the COGA document, and the final characterization of the issues NeuroAccess aims to identify with a set of illustrative examples.

The 'NeuroAccess-Pipeline' directory contains the set of agents that encompass our framework, the set of inputs used to evaluate the six applications, their corresponding outputs, and the overview of the time it took to run the complete pipeline on each application.


## Detailed Description

#### Issue-Characterization
The 'Issue-Characterization' directory contains two files and one folder:
- 'list-of-scs-with-neurodivergent-benefits' which contains the WCAG SCs identified that explicitly state benefits for neurodivergent users (for a total of 44 SCs).
- 'sc-to-dp-concrete-mapping' which portrays the 28 SCs for which a concrete mapping was established
- 'issues-definitiond-and-examples' contain one file for each categorization explaing the final definition of each issue, aside from giving an illustrative example for each of the categories.

#### NeuroAccess-Pipeline
The 'NeuroAccess-Pipeline' directory contains three main subdirectories and one additonal file:
- '.claude' is the home for all the agents that encompass our framework. Inside the 'agents' directory, there are four additional directories: 'clear-location', 'clear-purpose', 'consitent-functionality', and 'personas'. The first three have the three agents corresponding to each category: annotator, tester, and report compiler, while the other has the description for the four personas used, one file per persona (more personas can be added to the framework). Regarding the extra file, 'accessibility-report-compiler', is the agent that summarizes the reports received from the report  
- 'inputs' contains the inputs used for our evalution, both the Groundhog and DroidBot output, and the outputs generated by the annotators.
- 'output' contains the reports for all the applications evaluates
- 'CLAUDE.md' works as the orchestrator of our framework
- 'pipeline-run-time' shows the version of the application use and the time it took to run the full pipeline on each application. The file also shows for each application the individual time per category.
