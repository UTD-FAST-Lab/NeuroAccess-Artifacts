## Purpose
This artifact contains the related documentation for the issue characterization process and the NeuroAccess pipeline for the paper ***"NeuroAccess: Agentic Persona-Aware Detection of Neurodivergent Accessibility Issues in Mobile Apps"***

The 'Issue-Characterization' directory contains the 44 identified Success Criteria (SCs) that explicitly mention benefits for neurodivergent users, the mapping of 28 of these SCs to the Design Patterns (DP) define in the COGA document, and the final characterization of the issues NeuroAccess aims to identify with a set of illustrative examples.

The 'NeuroAccess-Pipeline' directory contains the set of agents that encompass our framework, the set of inputs used to evaluate the six applications, their corresponding outputs (i.e., raw results), and the overview of the time it took to run the complete pipeline on each application.


## Detailed Description

#### Issue-Characterization
The 'Issue-Characterization' directory contains two files and one folder:
- 'list-of-scs-with-neurodivergent-benefits' which contains the WCAG SCs identified that explicitly state benefits for neurodivergent users (for a total of 44 SCs). 
- 'sc-to-dp-concrete-mapping' which portrays the 28 SCs for which a concrete mapping was established to DPs.
- 'issues-definition-and-examples' contain one file for each category explaining the final definition of each issue, aside from giving an illustrative example for each of the categories. This document will provide deeper understanding what specific behaviors NeuroAccess agents will evaluate.

#### NeuroAccess-Pipeline
The 'NeuroAccess-Pipeline' directory contains three main subdirectories and one additional file:
- '.claude' is the home for all the agents that encompass our framework. Inside the 'agents' directory, there are four additional directories: 'clear-location', 'clear-purpose', 'consistent-functionality', and 'personas'. The first three contain the three agents corresponding to each category: annotator, tester, and report compiler, while the other contains the description for the four personas used, one file per persona (more personas can be added to the framework to extend evaluation coverage). Regarding the extra file, 'accessibility-report-compiler', is the agent that summarizes the reports received from the report compilers and produces the final accessibility assessment.
- 'inputs' contains the inputs used for our evaluation, both the Groundhog and DroidBot output, and the outputs generated by the annotators of each category. These serve as the starting point for pipeline execution and can be used to reproduce results.
- 'output' contains the reports for all the applications evaluated, meaning it has the raw results for each stage of the pipeline per application before the analysis that was performed. These provide an overview of the pipeline's findings for each tested application.
- 'CLAUDE.md' works as the orchestrator of our framework and contains the central instructions for running the complete pipeline.
- 'pipeline-run-time' shows the version of the application used and the time it took to run the full pipeline on each application. The file also shows for each application the individual time per category, providing performance benchmarks.

## How to Use This Artifact

**To understand NeuroAccess detection categories**: Begin with 'Issue-Characterization/issues-definition-and-examples' to see what problems NeuroAccess identifies.

**To run the pipeline**: Use the prompt `Run CLAUDE.md on [AppName]` where [AppName] is the name of the application you want to evaluate.

**To reproduce or extend results**: Reference 'inputs/' for sample data and 'output/' for expected results from each application evaluation phase.

**To add new detection categories**: Extend the personas in '.claude/agents/personas/' and create corresponding annotator, tester, and report compiler agents for the new category.
